# 测试与运维手册

本文用于发布前验收、故障排查、云端备份和回滚。命令均在仓库根目录执行。

## 1. 发布门槛

只有同时满足以下条件才允许发布：

1. Python、JavaScript 和 HTML 语法检查通过。
2. 记忆、同步、模型主备、公告更新、认证和隐私测试通过。
3. `dist/` 与 `dist-owner/` 由当前代码重新构建。
4. 桌面 `1280 x 720`、手机 `393 x 852` 的核心流程无横向溢出、遮挡或死按钮。
5. 发布前已创建生产全量快照，Git 中没有密钥、私人 JSON、上传图片或构建目录。
6. 发布后生产健康、登录、首页、同步与关键页面复核通过。

## 4. 手工模块验收

### 首页、PWA 与天气

- 首次打开时先等待天气确定，不闪现默认晴天背景。
- 晴、阴、雨、雷雨、雾、雪、清晨分别命中正确桌面与移动背景。
- 热点、桌面导航、手机五栏导航和“更多”均能进入对应空间。
- “保存到主屏幕”后的名称为“阿栗”，图标为狗头，启动为 standalone。
- Service Worker 有新版本时显示刷新入口，刷新后内容生效。

### 公告板与资讯

- 默认收起，打开后可查看本期和往期；版本数等于实际归档数量。
- 周一、周三、周五 08:00 的说明与 Cron 一致。
- 相同 URL 或标题不重复；无新内容不新增版本；全部来源失败显示失败。
- 笔记、待读、归档、加入工具箱能保存，重新打开仍存在。
- 阅读笔记与原资讯关联，不覆盖原文。

### 黑板

- 每日题、换题、星标、星标筛选、历史聚类均可用。
- 空白或“不会”可得 0 分；有效观点不能无依据全 0。
- 重新核分会产生新结果，不破坏之前作答。
- 历史题可重做，并可手动选择第 1、2、3 次回答。
- 档案包含作答、诊断、阿栗帮答、标准答案、资料和评分证据。

### 成长田

- 五块土地位置正确，空地只显示知识专题空态，不显示种植操作。
- 聊天与专题分离；历史会话位于可收起侧栏；消息显示时间。
- 新对话不删除旧对话，问题回答聚焦当前输入。
- 单块浇水、摘取以及一键浇水、一键收成都能正确更新。
- 摘取后土地恢复空地，背包增加果实卡；专题有概念、对比、结论和表格。
- 生长速度有限，不能因一次普通聊天直接成熟。

### 树洞、旅行、卧室与密阁

- 树洞文字、签语、对话和影像可编辑或删除，封存内容不进入普通检索。
- 旅行新建页默认清空；地点、日期、照片和感悟保存后生成摘要并清空输入。
- 手机旅行页字段纵向重排，日期不留无意义空白。
- 卧室日夜背景和关灯状态正确，不再出现私人密阁过渡页。
- 密阁可查看、分类和遗忘普通记忆；封存内容需明确授权；系统能力状态真实。

### 工具箱、阿栗与语音

- “加入工具箱”后卡片可见且不重复，编辑、移动和删除可持久化。
- 阿栗只有收到 `ok=true` 的工具结果才说“已完成”，系统修改不能执行时直接说明。
- 主模型失败后自动使用备用模型；两者都失败时显示可诊断错误。
- 浏览器支持语音识别时可输入；不支持或拒绝权限时给出提示，不假装成功。

### 照片集

- 各相册格子尺寸一致，图片使用 `contain` 保持比例。
- 普通相册照片可删除；“小院的所有照片”只展示公共背景且不可删除。
- 密阁背景不进入“小院的所有照片”。

## 5. 跨设备与记忆专项

跨设备至少使用两个独立浏览器配置执行：

1. 设备 A 登录并新增旅行记录 A；设备 B 新增记录 B；等待同步后两端都看到 A+B。
2. 两端修改同一记录并写入不同 `updatedAt`；最终保留较新版本。
3. A 删除记录，B 离线保留旧副本；B 上线后记录仍保持删除。
4. 删除同步完成后主人明确重新创建同一条记录，`revive` 操作可以恢复；无此操作的旧副本仍被阻止。
5. 一端刷新或重新登录，结构化状态从云端恢复。
6. 新输入“请记住”后形成证据与卡片；普通回答只检索相关非封存记忆。
7. 重复证据满足阈值后可晋升；冲突时保留证据链并按规则决策。
8. 树洞或明确秘密进入封存区，不出现在普通档案和普通对话上下文。
9. 执行彻底遗忘后，旧设备同步不能复活该卡片。

当前结论：文字、答案、专题、任务、记忆等结构化数据可跨设备同步；新上传图片尚无 R2，不属于已保证的永久跨设备数据。

## 7. 备份、部署与生产验证

### 发布前备份

公司网络下优先使用 Wrangler 传输：

```bash
python3 scripts/cloud_sync.py status --transport wrangler
python3 scripts/cloud_sync.py backup --transport wrangler
```

记录生成的 `full-snapshots/...` 键。不要把导出的私人 JSON 提交到 Git。

### 构建与部署主人版

```bash
python3 scripts/build_cloud.py --mode owner
python3 scripts/cloud_owner_test.py
node scripts/cloud_worker_test.mjs

cd cloudflare
wrangler deploy --config wrangler.toml
```

如系统 PATH 没有 Wrangler，可使用 `npx wrangler` 或已安装的 Wrangler 绝对路径。口令与模型密钥只能通过 `wrangler secret put` 管理。

### 生产验证

```bash
curl -I https://dcxin.neuralnode.top/
curl -sS https://dcxin.neuralnode.top/api/status
```

- 未登录首页返回登录界面，狗头图标可加载。
- 正确口令可进入；错误计数、锁定和成功清零符合规则。
- `/api/status` 的运行模式、认证和存储状态正确。
- 登录后核对首页天气、公告状态、成长田、旅行和密阁。
- 在生产新增一条临时结构化记录，从另一设备确认后删除，再确认删除同步。

## 8. 回滚与恢复

代码回滚使用上一个已知正常 Git 提交重新构建并部署，不使用强制推送覆盖历史。数据回滚步骤：

1. 先对当前生产数据创建新的全量备份。
2. 导出目标历史快照并人工确认时间、键数量和私人实例。
3. 使用显式覆盖参数恢复：

```bash
python3 scripts/cloud_sync.py push --transport wrangler --confirm-cloud-overwrite
```

4. 恢复后运行状态检查和跨设备抽查。

不要用旧电脑的 `core/` 目录直接覆盖生产云端，也不要删除 tombstone 后再导入旧数据。
